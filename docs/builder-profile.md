## Project Goals

STAR already ships Pipeline A ("Build the Room") and is deployed to Cloud Run. This cycle is a
**three-part extension**, in the order Este set:

1. **Google sign-in** — replace anonymous Firebase auth with `GoogleAuthProvider`. Server-side
   verification in `star/auth.py` already accepts any Firebase ID token regardless of provider,
   so this is near-zero backend work. Makes `uid` a real identity instead of a throwaway.
2. **HTTPS MCP server** inside `star/server.py`, exposing `list_rooms`, `get_room`, `build_room`
   (and later `check_scene`). Per-user bearer-token auth; OAuth 2.1 AS explicitly **deferred**.
3. **Pipeline B — Script Check** (`check_scene`): ClaimExtractor → Verifier → Annotator, then
   exposed over MCP.

**Overarching outcome:** a hackathon submission that survives Stage One (license visible, SDKs
imported *and* called) and scores on Stage Two (implementation / design / impact / idea).

**The governing constraint, from `docs/HANDOFF.md`:** deadline **Sun Sep 7 2026, 2:00 PM PT**,
target submission **Sep 5** — 26 days from this profile's date. Submission requires a hosted URL,
a public repo with a visible MIT license, and a ≤3-min demo video. **An MCP server is not on that
list; Pipeline B is described in the handoff as "the demo's emotional peak."** `/scope` owns this
tradeoff — it is the first real fork of the cycle, and it is a sequencing question, not a
scope-cut question.

## Design Direction

Strong, decided, and documented — not a greenfield question. Source: [`docs/design/DIRECTION.md`](design/DIRECTION.md)
(decided 2026-08-09), backed by four research files in `docs/design/`.

**The direction: THE MORGUE** — the newspaper clipping library behind the newsroom, where nothing
gets filed without a stamp saying who found it, where, and when. Chosen on one test: the metaphor
*describes* the system rather than dressing it (`LedgerEntry` ↔ a clipping file, `Finding.unverified_urls`
↔ an unstamped clip, `Category` ↔ four subject drawers).

**Palette:** Cabinet Green `#232B27` (ground), Drawer Shadow `#171D1A`, Manila `#D2B98C` (folder stock),
Aniline `#5C3D91` (filed and verified), Oxide Red `#B3341F` (flagged), Pencil `#7E8B7F` (metadata / unverifiable).

**Type:** Archivo Narrow (display/labels), Newsreader (body, real `opsz` axis), Sligoil (utility mono).
All SIL OFL, self-hosted — **no Google Fonts CDN**, per the zero-third-party-request rule.

**Two rules that make or break it:** Manila owns >40% of the room's pixel area in the filed state;
the stamp stays typographic (no distress textures, no rotation past 2.5°).

**Seven behavioural obligations** the research imposes, carried forward into `/prd` and `/spec`:
every finding shows the scene it unlocks; every citation is click-through; say what was *actually*
checked (never "verified"); show real uncertainty; state treatment retention in the intake before
the paste; never promise a duration; distinguish source *type*, not just count.

majors would break Pipeline A.

**Hard constraints `/spec` must not violate:**
- **Runtime AI is Google Cloud only.** Gemini via `google-adk`/`google-genai`. No other AI
  provider anywhere in what the project runs. ADK ships adapters for other providers — never use them.
- **Parallel Search API must be called at runtime** via the official `parallel-web` SDK
  (`star/tools/parallel_search.py`). This is the partner-track pass/fail check.
- **New code only, authored in-window** (contest opened Jul 27). Never copy from
  `writer-studio-template` — its ideas are fair game, its code is not.
- **Single-instance deployment is load-bearing, not tuning.** `scripts/deploy.sh` pins
  `--max-instances=1 --min-instances=1 --no-cpu-throttling`; `_runs`, `_ip_limiter`, and
  `_daily_cap` are in-memory module state. Anything that scales past one instance moves all
  three to a shared store **in the same change**. This is why the MCP server must live inside
  `star/server.py` rather than as a separate service.
